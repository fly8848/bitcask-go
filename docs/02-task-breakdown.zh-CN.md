# 02 开发任务拆分

核心思想：bitcask 只有两种操作——追加写 + 内存索引。磁盘记录格式与包结构由任务 1 决定，后续任务都依赖它，所以第一个任务务必把格式定清楚。

## 总览

| 阶段 | 任务 | 交付物 | 预计工时 |
|------|------|--------|----------|
| 1 | 记录编解码 | `record` 包 + 测试 | 2h |
| 2 | 数据文件管理 | `storage` 包 + 测试 | 3h |
| 3 | 引擎主体 | `engine` 包 + 测试 | 3h |
| 4 | 启动恢复 | 恢复逻辑 + 测试 | 2h |
| 5 | 合并压缩 | `merge` + 测试 | 3h |
| 6 | API 打磨与模糊测试 | 文档、随机测试 | 2h |

## 任务 1：记录编解码（record 包）

- [x] **设计磁盘格式**：`key 长度(4B) | value 长度(4B) | key | value`，再加 4B CRC 校验（建议放头部，读取时先验 CRC）；value 长度为 0 表示墓碑（删除标记）。字节序自定（大端/小端），全项目统一。
- [x] 实现 `LogRecord` 结构体（Key/Value/是否删除）+ 编码为字节、解码回结构体。
- [x] 测试：往返一致性、空 key/value、长 key、CRC 被篡改时解码报错。
- 完成条件：`go test ./...` 全绿。

## 任务 2：数据文件管理（storage 包）

- [x] 数据文件按递增 id 命名（如 `000000001.data`），id 由文件名解析。
- [x] 追加写 API：`Write(record) -> (fileId, offset)`；写满阈值（如 4MB）自动滚动新活跃文件。
- [x] 读 API：`Read(fileId, offset) -> LogRecord`，只按需读该记录长度。
- [x] 文件描述符管理：活跃文件保持打开，旧文件按需打开/缓存。
- 测试：滚动边界（正好写满/超一字节）、跨文件读写。
- 完成条件：`go test ./...` 全绿。

## 任务 3：引擎主体（engine 包）

- [x] `New(options)`：打开数据目录、加载活跃文件、构建空索引。
- [x] `Put(key, value)`：编码 -> 追加写 -> 更新索引 `map[string]LogPos{fileId, offset}`。
- [x] `Get(key)`：索引查不到返回 `ErrKeyNotFound`；查到了用 LogPos 读回并验证 CRC。
- [x] `Delete(key)`：追加写墓碑记录 + 删除索引。
- [x] `ListKeys()`：返回索引中所有 key。
- [x] `Close()`：关闭文件句柄。
- [x] 测试：增删改查全流程、覆盖写（同 key 写两次读新值）、删除后 Get 报错。
- 完成条件：`go test ./...` 全绿。

## 任务 4：启动恢复

- [ ] 打开已有数据目录时，按 id 从小到大扫描所有数据文件，重建索引（墓碑记录跳过）；记录尾部损坏（CRC 失败）则停止该文件解析。
- 测试：写入 -> 关闭 -> 重开 -> 数据完整；手动截断文件尾部模拟崩溃，重开不报错且丢弃坏记录。
- 完成条件：`go test ./...` 全绿。

## 任务 5：合并压缩（merge 包）

- [ ] 扫描全部数据文件，按 key 收集**最新**位置；统计无效数据量（被覆盖或已删除的旧记录）。
- [ ] 把有效记录写入新文件（新 id），原子替换后删除旧文件，更新索引位置。
- [ ] 活跃文件参与合并后，新写入落到新活跃文件，保证合并期间不丢写。
- 测试：合并前/后数据一致、目录中只有新文件、随机操作后合并再校验全部 key。
- 完成条件：`go test ./...` 全绿。

## 任务 6：API 打磨与模糊测试

- [ ] 错误语义整理：`ErrKeyNotFound`、`ErrEmptyKey`、`ErrDataDirNotExist` 等哨兵错误。
- [ ] 随机操作测试：随机 Put/Delete N 次后重启再合并，与内存模型比对全部 key-value。
- [ ] 补 README：用法示例、格式说明、与 bitcask 论文的对应关系。
- 完成条件：`go test ./...`、`go vet ./...` 全绿，README 就绪。
